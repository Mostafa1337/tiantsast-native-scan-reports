# TIANTSAST-NATIVE Scan Reports

Security scan reports generated by **TIANTSAST-NATIVE**, a private DEX-native Android SAST engine written in Rust.

The engine analyzes APKs directly on DEX — no decompilation in the analysis path, no standalone CFG stage:

```
APK → DEX → IR → Call Graph (CHA) → PTA → ICC → sparse taint → Detection
```

JADX is used only for evidence snippets in the HTML reports — never for the analysis itself. A CFG survives only as basic-block successors inside taint lowering; the call graph is class-hierarchy analysis and the points-to analysis runs without it.

112 detection rules across 23 vulnerability families, plus 13 semantic WebView rules (WV-001…WV-013). Every finding carries provenance resolved against the real manifest (attacker-entry / ICC-derived / internal / unknown), machine-readable attack paths, and DEX-level source-to-sink traces.

## How to View a Report

1. Download the HTML report file you want to inspect.
2. Open the downloaded file in any web browser (Chrome, Firefox, Edge, etc.).
3. The report renders in your browser — no server needed.

## Report Format (grouped HTML)

Each report is a single portable file containing:

- **Category cards** — findings grouped by vulnerability family (Intent redirection, WebView, file, network, …), each with a description, remediation, and CWE reference
- **Per-finding attack paths** — EXTERNAL ENTRY → SOURCE → data flow → SECURITY BOUNDARY → SINK, resolved at DEX register level
- **Provenance** — attacker-entry / ICC-derived / internal / unknown, resolved against the app's real manifest
- **Embedded evidence** — DEX statements and decompiled windows stored inside the file (rendered on demand, inert at load time)
- **Suppressed / library sections** — internal-provenance and library-only flows are demoted, not deleted

## The securoid-merged Lab App

The [securoid-merged](securoid-merged/) folder contains the scanned APK together with its report, so findings can be reproduced or re-scanned with any tool.

The app is a **validation lab**: it reproduces vulnerability patterns documented in public Android security research — including the `CRITICAL: JavaScript bridge → command execution (ActionBridge)` flow (the classic dangerous-bridge pattern) and the `Intent.parseUri` redirection flows in WebViewClient callbacks — **all documented by other researchers**. None of these are real-world findings or original discoveries: they are known patterns rebuilt as ground truth so the engine can prove it rediscovers them with correct provenance and complete traces. An engine that cannot rediscover known vulnerabilities has no business hunting unknown ones.
